\begin{abstract}
An invented detail can be an error in a factual summary and an expected
part of a fictional story. We argue that evaluating hallucinations in
large language model outputs therefore requires distinguishing what the
reference evidence establishes from what the task permits. We propose an
explicit \emph{truth contract} with three components: a task oracle that
specifies the reference evidence and checking procedures, a permission
scope that states what content is allowed or excluded, and required status
marking that states how the response must present that content.
The framework evaluates individual claims in context and labels them as
grounded, hallucination, or \emph{licensed divergence}. Claims left unknown
or contradicted by the reference receive the licensed-divergence label
when the task permits them and their presentation satisfies the required
marking. Permission does not change what the reference states or
establish creative value. A descriptive comparison of fifty-three selected
evaluation resources examines how existing designs represent these
conditions. Four examples illustrate how changes in reference evidence,
permission scope, or required status marking affect evaluation. We outline
studies to test whether evaluators can apply the framework reliably and
how claim labels can inform an assessment of the whole response.
\end{abstract}

\section{Introduction}\label{sec:intro}

Large language models (LLMs) can produce fluent statements that contradict
available evidence or cannot be verified from it. 
Such statements are commonly discussed as hallucinations in factuality evaluation, including source-faithfulness tasks \citep{ji_survey_2023,huang_survey_2025}.
Although LLMs can handle increasingly complex tasks, hallucinations remain a problem.
Across successive generations, newer and larger models do not
consistently exhibit lower hallucination rates. Results from AA-Omniscience benchmarks show
persistent weaknesses in factual accuracy and abstention, and its August 26,
2026 leaderboard snapshot shows no consistent decrease in hallucination rate
with open-weight model size
\citep{jackson_aaomniscience_2025,artificialanalysis_omniscience_leaderboard_2026}.
Hallucination therefore remains an unresolved challenge. Moreover, Banerjee
et al.\ argue that hallucination is inherent to the mathematical and logical
structure of LLMs, such that scaling and architectural improvements alone
cannot eliminate it \citep{banerjee_llms_2024}.
Factuality and source-faithfulness evaluations check generated content against external references or supplied documents \citep{maynez_faithfulness_2020,kryscinski_evaluating_2020,min_factscore_2023}.
These checks are essential when a task requires factual accuracy.
Yet LLMs are also used for brainstorming, hypothesis generation,  fiction and other creative tasks
where users may explicitly request content that existing evidence does not
support \citep{franceschelli_creativity_2024,jiang_survey_2024}.
A factual summarization task may reject an unsupported explanation, whereas a hypothesis-generation task may allow it.

Treating every creative generated claim beyond the available evidence as a
hallucination would penalize licensed divergence that some tasks allow or even require.

The opposite problem occurs when evaluation focuses on creativity.
Creativity evaluations look at metrics such as novelty, usefulness, and
task-specific quality
\citep{runco_standard_2012,hou_creativityprism_2025,zhao_assessing_2025}.
These metrics alone do not show whether the information in a response is
supported by available sources or whether the task permits unsupported
content.
Many creativity evaluations in the existing literature measure creative
performance without checking at the same time whether the information is
supported by available sources (Section~\ref{sec:methodology}).
A response can be creative but contain unsupported
information. Conversely, it can be factually accurate but fail to meet the creative goal.


The distinction is simple: the same sentence can be acceptable in one task and
a hallucination in another. For example, consider two museum labeling tasks with different prompts based on the same
source, paired with the same constructed response in Figure~\ref{fig:prompt-to-claim}. 
The response contains the following text: ``One possible reconstruction places the complete
stele near a temple entrance.'' The source does not confirm or deny the claim in this 
sentence.
For a factual task, this is a hallucination because the task may require only
facts supported by the source. In a creative task, it can be a licensed divergence
if the task allows this kind of addition and the response clearly presents it
as a possibility.
Therefore, if the response presents this possibility as a fact, it becomes a hallucination
because it fails the requirement to present the reconstruction as a possibility.




\paragraph{Our position}
We argue that hallucination evaluation should consider both the available
evidence and the task instructions. We call this combination a \emph{truth
contract}. It answers three questions: What reference evidence and checking procedure should be used to check the response? What content does the task permit or exclude beyond the reference evidence? How must the response present such content? 
These questions should be answered from the task context
before the response is evaluated.
The truth contract makes evaluation rules explicit. Content supported by the reference receives the grounded label unless the task explicitly excludes it.
By contrast, content that goes beyond or contradicts the reference receives the \emph{licensed divergence} (\LD) label only when the task permits it and the response presents it as required.
Otherwise, this content is classified as a
hallucination. Licensed divergence therefore indicates
that unsupported content was both permitted and clearly presented as such. It
does not indicate that the content is true. Our position is that the available evidence and the task instructions should
be evaluated together.

\paragraph{Contributions}
This position paper makes three contributions. First, we introduce the
\emph{truth contract} for evaluating hallucinations in LLM-generated text. It states what evidence should be used, what the task
allows beyond that evidence, and how such content should be presented. This
contract helps distinguish grounded content, hallucinations, and licensed
divergence (Section~\ref{sec:framework}).

Second, we propose rules for labeling individual claims based on the \emph{truth contract}.


Third, we compare fifty-three selected evaluation resources and illustrate the
framework with four examples
(Sections~\ref{sec:methodology} and~\ref{sec:examples}).
The research agenda in Section~\ref{sec:agenda} asks whether the framework can be applied reliably and improves evaluation.

Section~\ref{sec:related} situates the proposal among work on factuality,
instruction following, and creativity. Section~\ref{sec:framework} defines
the contract and the claim-labeling rule. Section~\ref{sec:methodology}
compares how 53 selected evaluation resources represent evidence,
permission, and required status marking. Section~\ref{sec:examples} illustrates the rule
with four constructed examples. Sections~\ref{sec:agenda} and
\ref{sec:discussion} describe the studies needed and the scope of the proposal.

\section{Related Work}\label{sec:related}

Existing work provides methods for checking evidence, identifying claims,
evaluating task instructions, and assessing creativity. This section explains
how those methods relate to the evidence, permission, and marking conditions
introduced above. Section~\ref{sec:framework} then formalizes the contract.

\subsection{Evidence Relations and Hallucination Taxonomies}

Hallucination surveys distinguish several kinds of mismatch.
\citet{ji_survey_2023} separate source contradictions from content that cannot
be verified from the source. \citet{huang_survey_2025} distinguish factuality
and faithfulness failures, including inconsistencies with instructions,
context, or logic. These classifications describe different kinds of error.
An evaluation must still specify which evidence and checking procedure it uses.

Source-faithfulness evaluation asks whether a response agrees with a supplied
document \citep{maynez_faithfulness_2020}. For example, FactCC predicts whether
each summary sentence is consistent with the document and identifies
passages that help explain this prediction \citep{kryscinski_evaluating_2020}.
QAGS generates questions from the summary, answers them using the summary
and the source document separately, and compares the answers. Different
answers suggest a factual inconsistency \citep{wang_asking_2020}.

Factuality evaluation can also search external sources for evidence.
FActScore breaks a response into individual claims, retrieves relevant
passages from a knowledge source, and estimates the proportion of claims
they support \citep{min_factscore_2023}. VeriScore focuses on claims that
can be checked against external evidence, retrieves web evidence, and
checks whether it supports them \citep{song_veriscore_2024}.
These checking procedures can be used within a textual task oracle.
The evaluation protocol must still specify which sources count as reference
evidence and how to distinguish contradiction from missing evidence.
The truth contract proposed here also records what the task permits the
response to add or change beyond that evidence. This permission does not
change whether the reference supports, contradicts, or leaves a claim unknown.


Attribution evaluation makes the relation to an identified source explicit.
AIS checks whether an utterance can be interpreted in context and supported
according to that source, separating attribution from absolute factual truth
\citep{rashkin_ais_2023}. ALCE requires citations and checks their support
and relevance alongside answer correctness \citep{gao_alce_2023}.
A citation identifies the evidential basis of a statement; it does not by
itself identify the statement as hypothetical or fictional.

\subsection{Claim-Level Evaluation}\label{subsec:extraction}

Evaluating claims separately helps assess responses that mix supported and
unsupported content.
FActScore and VeriScore extract claims and check them against evidence
\citep{min_factscore_2023,song_veriscore_2024}. Claimify focuses on extracting
claims whose meaning can be understood and checked independently
\citep{metropolitansky_claimify_2025}.
We distinguish three steps to explain how a response is prepared and checked:
\begin{itemize}
\item \emph{Claim extraction} identifies the statements in the response
that will be evaluated separately. One sentence can contain several claims.
FActScore, for example, breaks the response into atomic facts, each expressing
one piece of information \citep{min_factscore_2023}.
\item \emph{Claim recovery in context} is the term we use for identifying
what an extracted statement means in its surrounding text. For example,
the context can identify which object ``the stone'' refers to. Recovery
preserves the claim's meaning, including its dates and qualifications.
Work on decontextualization similarly rewrites a statement so that it can
be understood on its own while preserving its meaning
\citep{choi_decontextualization_2021}. Claimify also addresses ambiguity in
interpreting the text before extracting a claim
\citep{metropolitansky_claimify_2025}.
\item \emph{Claim verification} compares the recovered claim with
reference evidence to check whether that evidence supports it. FActScore
checks support against a reliable source, while VeriScore retrieves web
evidence for claims that can be verified
\citep{min_factscore_2023,song_veriscore_2024}.
\end{itemize}
These steps have different roles: extraction identifies the words to
evaluate, recovery identifies what they mean, and verification checks
the evidence. Our framework combines this claim-level evaluation with
the task's permission scope and required status marking to determine
each claim's label.

The surrounding text helps determine what a statement means and what the
speaker presents as true \citep{stalnaker_assertion_1978,clark_using_1996}.

Research on \emph{hedging} examines how writers make clear that a claim
is uncertain or open to discussion. Words such as ``may'' or ``possibly''
can present a claim as a possibility. Hedging can also show that the writer
is offering an interpretation that others may question
\citep{hyland_hedging_1996}.

Existing evaluations also check uncertainty expression.
AbstentionBench judges whether a response abstains when the sample requires it
\citep{kirichenko_abstentionbench_2025}. UNCLE evaluates uncertainty by answer
aspect, while LoGU handles it for individual claims in long responses
\citep{yang_uncle_2025,yang_logu_2025}. Both distinguish factual correctness
from selective uncertainty, using short-answer probes to estimate what the
model knows.

Faithful expression of intrinsic uncertainty is a separate target:
\citet{yona_faithful_2024} compare linguistic decisiveness with confidence
estimated from sampled answers. Estimated model confidence does not
determine whether designated reference evidence supports a claim.

Our \emph{observed status marking} builds on this work by recording how
a claim is presented in the response. It is an annotation of the response,
using the labels \textsc{established}, \textsc{hypothetical}, and
\textsc{fictional} described in Section~\ref{subsec:contract-checks}. Hedging is one
way to signal a possibility. The context can also identify a claim as
part of fiction, even when its sentence contains no words such as ``may''
or ``possibly'' \citep{searle_logical_1975}. The annotation therefore
records the presentation of the claim in context, including facts,
possibilities, and fiction.

The \emph{required status marking} specifies the task's condition for
that presentation. This gives the evaluator two separate records: what
the response expresses and what the task asks for. Our contribution is
to combine their comparison with the reference evidence and permission
scope for each claim. A possibility clearly signaled by hedging must
still be permitted by the task to receive licensed divergence.
Section~\ref{subsec:contract-checks} explains these records and their use in the
framework.

Missing claims or splitting the response incorrectly can also affect the
evaluation
\citep{wanner_closer_2024,metropolitansky_claimify_2025}.
These studies motivate preserving each claim's meaning and context when
preparing it for evaluation.

\subsection{Instruction Following, Permission, and Marking}

Instruction-following evaluation checks whether a response meets the
constraints in a request. IFEval uses instructions whose satisfaction can
be checked directly, such as a required word count or keyword
\citep{zhou_ifeval_2023}; other benchmarks examine several dimensions of
instruction following \citep{ye_muldimif_2025}. FaithQA examines whether a
response omits or misinterprets parts of the query, including in creative
writing tasks \citep{hao_faithqa_2025}.
Work on instruction following and source faithfulness also examines the
trade-off between following open-ended instructions and grounding responses
in a supplied context \citep{wu_dancing_2024}.

Existing task constraints can already specify what content a response
must include or exclude. Permission scope overlaps with these constraints:
it specifies which additions or changes are allowed when the reference
evidence does not support the content. The general idea of controlling
what a task allows is therefore already present in these evaluations.

Question-answering protocols can distinguish problematic premises from
conditions supplied for reasoning. (QA)$^2$ evaluates answers to questions
with false or unverifiable assumptions \citep{kim_qa2_2023}.
FaithEval requires answers to follow supplied contexts, including contexts
that contradict ordinary world knowledge, and requests unknown or conflict
responses in designated tasks \citep{ming_faitheval_2025}.
IfQA supplies an explicit counterfactual condition for reasoning
\citep{yu_ifqa_2023}. Correcting a false premise and reasoning under a
counterfactual premise are different task obligations.

Fictional settings can also define the reference and allowed knowledge.
TimeChara evaluates responses against narrative time and perspective,
including whether a character expresses unawareness of events outside
that perspective \citep{ahn_timechara_2024}. Reference-relative evaluation
is therefore already operationalized within fictional worlds.

Our framework builds on the study of how claims are presented and on
evaluation of task constraints. Its contribution is to combine these
checks with reference evidence for each claim. 
A permission describes what a response \emph{may} introduce, whereas an
obligation specifies what it \emph{must} do. Allowing a reconstruction does
not require the response to produce one. If it does, the required status
marking specifies how it must be presented. Checking each instruction
separately shows which requirements the response meets and which it
misses \citep{lee_mcjudgebench_2026}. A single overall response score can
hide these differences.

\subsection{Creativity and Task Quality}\label{subsec:creativity}

Creativity research commonly asks whether an idea differs from familiar
ideas (\emph{novelty}) and whether it serves a purpose or fits the task
(\emph{usefulness} or \emph{appropriateness})
\citep{runco_standard_2012,diedrich_are_2015}.
Their relationship depends on the evaluation setting, and combining them can
hide differences between dimensions \citep{pichot_reflective_2024}.

LLM evaluations make these questions more specific. CreativityPrism assesses
how well an output works for its task, such as whether a story is coherent
or code executes correctly (\emph{quality}); how it differs from existing
content (\emph{novelty}); and how varied the generated content is
(\emph{diversity}) \citep{hou_creativityprism_2025}.
Other evaluations consider how many relevant ideas a response offers, how
many different approaches it explores, how unusual its ideas are, and how
fully it develops them \citep{zhao_assessing_2025}. For creative writing,
\citet{li_automated_2025} compare generated stories with human-written
reference stories using a set of creativity tests.

\citet{si_ideas_2025} evaluate research proposals through blind expert
judgments of novelty and feasibility, among other criteria.
Their template includes a proposed method and an experiment plan, which
already present the output as a proposal. These judgments do not verify
each factual claim embedded in it.

These criteria ask whether a response is original, useful for its task,
or well written. Factuality asks whether its claims are supported. In this
paper, permission asks another question: did the task allow the response
to introduce that content? A response can be clear and engaging while
introducing an unauthorized claim; a permitted reconstruction can be dull
or add little to the reader's understanding. Thus a favorable quality
judgment does not settle whether the truth contract is satisfied.

Usefulness depends on the task. In a museum explanation, a reconstruction
might help a visitor understand an incomplete object; in a strict factual
summary, that same addition may be outside the instructions. This example
separates permission from creative value. Other studies examine whether a
response is factually correct and how much information it provides
\citep{wu_balancing_2025,gong_factuality_2026}. Providing more information
does not necessarily make a passage useful for the task or easy to understand.

\subsection{Hallucination and Creativity}

Some studies connect hallucination research with creativity research by
asking whether generating content beyond established evidence can help
produce new ideas. The survey by \citet{jiang_survey_2024} separates
proposing different ideas (\emph{divergent generation}) from checking and
selecting them (\emph{convergent evaluation}).

Empirical studies about hallucinations and creativity typically address specific tasks. \citet{sun_hallucinating_2024}
study mathematical problems, riddles, practical problems with limited
resources, and commonsense questions. They generate several reasoning paths
for each problem, keep those with correct final answers, and group similar
paths to measure the variety of approaches. Their use of ``good
hallucinations'' therefore concerns alternative reasoning paths that lead
to correct answers, not a general permission to invent facts.

\citet{he_shakespearean_2025} study factual question answering on TriviaQA
and Natural Questions. They generate answers using different internal
layers of the model and compare error rates with the variety of correct
answers. Their creativity measure captures that variety, rather than the
quality of a story or poem. These studies examine how generation choices
affect correctness and diversity; they do not establish which unsupported
claims a task permits.

Recent work also evaluates creative presentation under a source constraint.
StoryScore combines measures of scientific-story quality and grounding; its
hallucination component checks person and organization entities against the
source paper \citep{argese_storyscore_2026}. This is a targeted consistency
check, not a general decision about which unsupported claims a task permits.
Its aggregate weights are heuristic, and the reported findings are preliminary.
SimpleText 2026 Task~2 separates detection of new content, classification of
information distortions, and grounded generation with or without explicit
source attribution \citep{simpletext_task2_2026}. Its protocol provides a
concrete comparison for source-based evaluation; the name ``controlled
creativity'' does not itself authorize invented facts. These two designs
are discussed here as targeted additions to the literature review, outside
the 53-resource inventory in Section~\ref{sec:methodology}.

Related proposals discuss invented content, including content used to fill
gaps in historical records, and its possible value
\citep{sui_confabulation_2024,sui_critical_2025,yang_hicbench_2025}.

Our question comes before judging creative value: when the evidence does not
support a claim, does the task allow the response to introduce it? Fiction
also requires distinguishing what is presented as part of a story from what
is asserted about the real world \citep{searle_logical_1975}. This supports
recovering each claim in context before checking evidence and permission.

\subsection{Global Reasoning and Response Completeness}\label{subsec:global}

Verifying individual claims does not establish valid reasoning between them.
Research on long-form evaluation identifies this limitation
\citep{yan_logicscore_2026}, while work on reasoning and step-level evaluation
examines different units of failure
\citep{arcuschin_cot_2025,pham_grace_2026}.
A decision about whether a claim is supported or permitted does not
establish whether it follows logically from another claim.

Cross-claim consistency also requires comparison between statements
\citep{mundler_selfcontradictory_2024}. Individually licensed claims may be
mutually inconsistent. This requires a separate check across claims.

\emph{Completeness} asks whether the response includes the information
needed to answer the request. A response can contain only correct claims
and still leave out important information. Work on \emph{factual recall}
examines this by checking how much of the relevant information in a set of
reference facts is included in the response
\citep{liu_verifact_2025,jafari_recall_2026}.
Reasoning, consistency, and completeness therefore complement the contract
record; they are not implied by it.

Taken together, these studies provide ways to check evidence, identify claims,
and assess instructions and creative quality. Our position connects these
questions at the level of an individual claim: evidence states its
relation to the reference, while the task specifies what may be added or
changed and how it must be presented. The next section formalizes this
distinction as a truth contract.

\section{Framework}\label{sec:framework}

The museum example in Figure~\ref{fig:prompt-to-claim} poses an evaluation
problem: two tasks can require different judgments of the same generated
text. We evaluate the individual \emph{claims} in the response generated
by the model. A claim is content that a passage states or proposes about
an entity, property, or event. For example, a sentence may state where the
stone was found and when it was found; these details can be evaluated
separately. Claims are recovered in context so that their meaning and
presentation as fact, hypothesis, or fiction are preserved.

The example uses a constructed reference fragment: the stone was found
near Rosetta in 1799, bears a decree from 196 BCE in three scripts, and is
part of a larger stele probably displayed in a temple. This fragment is an
illustrative input, not a verbatim historical quotation. It does not specify
where the complete stele stood. The response adds: ``One possible
reconstruction places the complete stele near a temple entrance.'' The
reference leaves that placement unknown. A task restricted to supported
facts rejects it; a task permitting a plausible reconstruction can accept
it when it is presented as a possibility.

This comparison separates three questions: what the reference establishes,
what content the task permits, and how that content must be presented.
The reference and claim stay fixed while permission changes. We represent
these evaluation conditions as a \emph{truth contract}, then explain how
to recover claims and apply the contract to each one.

\subsection{The Truth Contract}\label{subsec:contract}

A truth contract records the reference evidence and checking procedure,
the content the response may introduce, and the presentation required for
that content. Its three components are:
\begin{itemize}
\item $O$, the \emph{task oracle}, specifies the reference evidence and
checking procedure used to evaluate the claims in the response;
\item $\Gamma$, the \emph{permission scope}, records which additions or
changes to the reference content are permitted, including explicit
requirements for invention;
\item $\mu$, the \emph{required status marking}, specifies how permitted
content must be presented, for example as a conjecture or as fiction.
\end{itemize}
Let $p$ denote the complete task context: the prompt, applicable instructions,
dialogue history, domain constraints, and supplied data. Its evaluation
conditions are represented by
\begin{equation}
\TC(p)=(O,\Gamma,\mu).
\label{eq:truth-contract}
\end{equation}
Thus $p$ is the input context; $\TC(p)$ is the contract specified for it.
The evaluator is the human, program, or combination of both that applies
the evaluation protocol. It fixes the contract independently of the response
being judged and does not expand permission afterward to accommodate that
response. If applicable instructions conflict, their priority must be
resolved and recorded; otherwise the contract is underspecified.

\paragraph{Task oracle}
The task oracle $O$ specifies both the reference evidence and the procedure
used to check the response. It can use supplied documents, retrieved
evidence, reference answers, or domain-specific checks. The evaluation
protocol fixes these choices before comparing responses and records the
sources, their versions, the time period they cover, and how conflicting
evidence is handled. People, programs, or both can carry out the checks.

For text, we treat the oracle as a black box that takes a response as input,
recovers its claims in context, and checks them against the designated
reference. For each claim it successfully checks, it returns an
\emph{evidence state}: the reference supports the claim (\textsc{entailed}),
contradicts it (\textsc{contradicted}), or neither supports nor contradicts
it (\textsc{unknown}). Claim extraction, claim recovery in context, and
claim verification, introduced in Section~\ref{subsec:extraction}, are parts
of this oracle. Sections~\ref{subsec:unit} and \ref{subsec:verification}
explain how these steps are used in the framework.

In the museum example, the oracle uses only the constructed reference
fragment. That fragment does not specify where the complete stele stood,
so the proposed temple-entrance placement is \textsc{unknown}. A different
reference can give a different evidence state, as Example~A in
Section~\ref{sec:examples} illustrates. Permission to invent does not change
what the designated reference establishes. We assume correct oracle
outputs in the constructed examples so that we can explain how the
evaluator then applies permission and marking requirements.

If a source is unavailable or a check cannot be completed, the evaluator
records a failure and leaves the claim unlabeled instead of assigning
\textsc{unknown}. Section~\ref{subsec:verification} and
Appendix~\ref{app:diagnostics} explain these failures.

\paragraph{Permission scope}
Permission scope $\Gamma$ records what the response may add or change beyond
the reference evidence. A permission rule specifies the content concerned
and the kind of addition or change allowed. In the museum task, the permission rule permits
plausible reconstructions of the stone's original placement when the
reference leaves that placement unknown. The proposed temple-entrance
placement falls within this rule. Changing the decree's known date or
predicting a future transfer of the stone falls outside it.

For a strict factual task, $\Gamma=\varnothing$: the set of permitted
additions or changes is empty, while supported facts remain allowed.
A task may also explicitly require invention in a specified part of the
response and exclude supported facts there. These exclusions are recorded
as additional scope rules and checked before assigning a label. A request
for fiction alone does not impose them: a story can include real places
or events.

\paragraph{Required status marking}
Required status marking $\mu$ records how the task requires permitted
content to be presented. It specifies the required status, such as a
possibility or fiction, and any instruction about how that status must be
made clear. For example, a task may require reconstructions to be presented
as possibilities, or explicitly require a heading such as ``Hypothesis.''
These conditions are taken from the prompt and other applicable
instructions.

In the museum task, $\mu$ requires a permitted reconstruction to be
presented as a conjecture. This is the presentation the evaluator will
look for in the response. The \emph{observed status marking} records how
the response actually presents each claim; Section~\ref{subsec:contract-checks}
explains how it is compared with $\mu$. Marking a claim as uncertain or
fictional never expands its permission scope.

This concern with communicating uncertainty relates to
\citet{yona_metacognition_2026}, who propose that a model's expressed
uncertainty should reflect its internal uncertainty. Here, $\mu$ describes
the presentation required by the task, including for hypotheses and fiction;
it does not measure the model's internal confidence.

Figure~\ref{fig:claim-label-annotation} shows how these three parameters
enter the evaluation pipeline. The task context fixes the truth contract.
The oracle then extracts response spans, recovers their claims in context,
and checks them against the reference evidence. The evaluator uses
$\Gamma$ and $\mu$ to check permission and presentation where the decision
rule requires them, then assigns claim labels. The frame groups these
results in a \emph{claim trace}: a record linking each claim to its words
in the response, evidence state, checks, and label. The following sections
explain these steps in that order.

\subsection{Response Text to Claims}\label{subsec:unit}

An LLM response can mix facts, suggestions, and storytelling. The first
stage of the pipeline identifies its claims and preserves the context
needed to interpret them. In Figure~\ref{fig:claim-label-annotation}, this
corresponds to the response spans and recovered claims.

Evaluating separate pieces of information is also the approach used by
FActScore, which breaks a response into atomic facts before checking their
support \citep{min_factscore_2023}. \emph{Claim extraction} finds the relevant
words in the response; we denote the passage for claim $i$ by $s_i$.

\emph{Claim recovery} identifies what those words mean in context. We write
the recovered claim content as $q_i^*$, preserving its meaning, entities,
qualifications, and dates. For example, in
Figure~\ref{fig:claim-label-annotation}, ``The stone was found near Rosetta
in 1799'' refers to the Rosetta Stone and specifies its discovery place and
date. Recovering the claim resolves ``the stone'' against the context while
retaining those details. This need to preserve meaning when making a
statement understandable on its own is also central to decontextualization
\citep{choi_decontextualization_2021}.

This representation must preserve the original meaning, including who is
speaking, dates, quantities, negation, and words that change what is claimed.
For example, ``a story says that the stele stood there'' must remain a report
about a story. It must not become an assertion that the stele really stood
there. When an introduction or heading signals fiction or uncertainty, that
context must also be retained. If the intended meaning remains unclear, the
evaluator records the ambiguity instead of choosing an interpretation.

Likewise, ``The text fragment does not confirm that the stele stood near a temple
entrance'' makes a claim about the source. It does not claim that the stele
stood there. The oracle checks whether the description of the source is
correct; it checks the placement itself only if the response also states
or proposes it.

Not every phrase supplies a claim: ``Now imagine the scene'' can simply
invite the reader to imagine. The evaluator excludes such passages and must
avoid missing claims, adding content absent from the response, or merging
statements that need separate judgments.
Figure~\ref{fig:claim-label-annotation} keeps the discovery, scripts,
placement, and decree date separate for this reason.
Appendix~\ref{app:diagnostics} describes these errors. The next section
explains how the oracle checks the recovered claims against evidence.

\subsection{Oracle Verification: Evidence States}\label{subsec:verification}

After extraction and recovery, the oracle performs \emph{claim verification}:
it checks each $q^*$ against its reference evidence. The resulting
\emph{evidence state}, written as $\mathrm{ES}$, records whether that evidence
supports the claim, contradicts it, or leaves it unknown. Successful
verification returns one of three states:
\begin{itemize}
\item \textsc{entailed}: the reference evidence supports the claim;
\item \textsc{contradicted}: the reference evidence contradicts the claim;
\item \textsc{unknown}: the reference evidence neither supports nor
contradicts the claim.
\end{itemize}
An \textsc{unknown} result means that the specified evidence neither supports
nor contradicts the claim. Consider ``One possible reconstruction places
the complete stele near a temple entrance.'' The museum text fragment says that
the stele was probably displayed in a temple, but does not specify its
placement near an entrance. That placement is therefore \textsc{unknown}
relative to the text fragment, before checking whether the task permits it.

This differs from a failed evaluation. If a required source is inaccessible,
a source conflict cannot be resolved, or the claim remains unclear, the
evaluator records the failure and leaves the affected claim unlabeled. Appendix~\ref{app:diagnostics} describes these failures.

At this stage, each recovered claim has its content $q^*$, the context
needed to interpret it, and its evidence state $\mathrm{ES}$. Procedural
failures are recorded alongside these results. In
Figure~\ref{fig:claim-label-annotation}, the oracle recovers four claims and
assigns two \textsc{entailed} states, one \textsc{unknown} state for the
placement, and one \textsc{contradicted} state for the decree date. These
states describe the relation to the evidence. The next section applies
the permission and presentation requirements already specified in the
truth contract.

\subsection{Checking Permission Scope and Required Status Marking}\label{subsec:contract-checks}

Once the oracle has recovered the claims and checked their evidence
states, the evaluator applies the permission scope $\Gamma$ and required
status marking $\mu$ fixed in Section~\ref{subsec:contract}. These checks
connect the evidence states to the claim labels in
Figure~\ref{fig:claim-label-annotation}. The decision rule in
Section~\ref{subsec:rule} specifies when each check is needed.

\paragraph{Permission check}
For content not supported by the reference, we write
$(q^*,\mathrm{ES})\in\Gamma$ when the scope rules permit the recovered claim
content $q^*$ in its evidence state $\mathrm{ES}$. The notation records both
what may be introduced and its relation to the evidence. Permission for an
unknown reconstruction, for example, need not include permission to
contradict a known date. Section~\ref{subsec:rule} explains how evidence states
and permission determine the label.

In the museum example, the reference leaves the temple-entrance placement
unknown and $\Gamma$ permits this kind of reconstruction. The permission
check therefore passes for that claim. Changing the decree's known date
falls outside the permission scope and fails the check.

\paragraph{Marking check}
The evaluator checks whether the response presents the claim as required
by $\mu$. It compares two records:
\begin{itemize}
\item \emph{Required status marking} $\mu$ is specified by the task: how
must permitted content be presented, and is a particular wording or
heading required? This is the condition that the response must satisfy.
\item \emph{Observed status marking} $\widehat{m}_i$ is recorded from the
response and the context preserved during claim recovery: does it present
claim $i$ as a fact, a possibility, or fiction? It describes the response;
it is not a task condition.
\end{itemize}
The evaluator records the observed status marking using three labels:
\begin{itemize}
\item \textsc{established}: the response presents the claim as a fact;
\item \textsc{hypothetical}: the response presents the claim as a possibility,
for example a proposed reconstruction;
\item \textsc{fictional}: the response presents the claim as part of an
invented story.
\end{itemize}
These labels describe how the response presents the claim. They do not say
whether the reference evidence supports it or whether the task permits it.

For example, the museum task requires reconstructions to be presented as
possibilities. ``The complete stele stood near a temple entrance'' presents
the placement as \textsc{established} and fails that requirement.
``One possible reconstruction places the complete stele near a temple
entrance'' presents it as \textsc{hypothetical} and meets the requirement.
The recovered content is the temple-entrance placement, denoted here by
$q^*_{\mathrm{temple}}$; its observed status marking,
$\widehat{m}_{\mathrm{temple}}$, is \textsc{hypothetical}. The separate claim
``The decree dates from 1799,'' denoted by $q^*_{1799}$, has observed status
marking \textsc{established}. The permission check remains separate from
this presentation check.

A task can add a specific presentation instruction, such as ``Put all
reconstructions under the heading `Hypothesis'.'' In that setting, the
response must also include the heading. Without it, the sentence still
presents a hypothesis, but the requested heading is missing. Example~C in
Section~\ref{sec:examples} illustrates this additional instruction; it does
not distinguish two kinds of hypothesis.

For the temple-entrance reconstruction in
Figure~\ref{fig:claim-label-annotation}, the permission check passes and
``One possible reconstruction'' satisfies $\mu$. These are the two checks
shown beneath its label. The next section explains how their results and
the evidence state determine that label.

For a claim $i$, $\mathrm{ES}_i$ denotes its relation to the reference evidence:
\textsc{entailed}, \textsc{contradicted}, or \textsc{unknown}.
The observed status marking $\widehat{m}_i$ describes how the response actually
presents that claim; $\mu$ specifies how the task requires it to be presented.
The index $i$ identifies a claim; $O$, $\Gamma$, and $\mu$ apply to the task.



\subsection{Combining Contract Results: Claim Labels}\label{subsec:rule}

The evaluator now combines each claim's evidence state with the permission
scope and required status marking specified for the task. Supported content receives
the grounded label (\Grd), unless the task explicitly excludes it. Content
that is \textsc{unknown} or \textsc{contradicted} requires two further checks:
does the task permit it, and does the response present it as required?
If both conditions hold, it receives \emph{licensed divergence} (\LD).
Otherwise, it receives \emph{hallucination} (\Hall).

Figure~\ref{fig:claim-label-annotation} illustrates the ordinary museum task.
The temple-entrance placement is \textsc{unknown}, but the task permits this
reconstruction. With ``One possible reconstruction,'' it receives \LD{};
with status marking \textsc{established}, it would receive \Hall{} for a marking failure.
The claim that the decree dates from 1799 contradicts the source and is not
permitted, so it receives \Hall{}. Adding ``possibly'' would not authorize it.

Permission can also depend on the evidence state. Allowing an unknown
reconstruction does not automatically allow a contradiction of a known date.
An alternate-history task could explicitly permit the changed date and
require \textsc{fictional} marking; the result would then be \LD{}, while $\mathrm{ES}$ would
remain \textsc{contradicted}.

This rule also covers a task that explicitly excludes supported facts.
Consider the instruction: ``Invent the discovery place and date for a
fictional version of the stone; do not reuse the real place or date.'' A
response giving only ``The stone was found near Rosetta in 1799'' provides
supported facts, but those facts are explicitly excluded here. The affected
claims receive \Hall{} with reason \textsc{out-of-scope}, while their evidence
state remains \textsc{entailed}. Under our proposed framework, the
hallucination label therefore includes a supported fact that violates an
explicit requirement for invented content. This exclusion must be stated
in the task; a request for fiction alone does not impose it.

The permission check uses the rules defined in Section~\ref{subsec:contract-checks}:
$(q^*,\mathrm{ES})\in\Gamma$ means that the addition or change is permitted;
$(q^*,\mathrm{ES})\notin\Gamma$ means that it is not. Explicit exclusions
of supported facts are checked separately under the scope rules.

Each hallucination receives a reason code. Use \textsc{out-of-scope} when
the content is not permitted or is explicitly excluded. Use
\textsc{marking-failure} when a departure is permitted but is not presented
as required. If both checks fail, \textsc{out-of-scope} takes priority.

processing; evaluation failures are handled as described in
Section~\ref{subsec:verification}.

addition. The label records whether the claim meets the contract; it does
not change what the oracle establishes. The result is a \emph{claim trace}:
a record of each claim, its evidence state, the checks applied, and its label.

\paragraph{Claim trace}\label{subsec:response}

A response can contain claims with different labels and reasons for failure.
The \emph{claim trace} records these decisions separately, linking each label
to the words in the response and the checks that led to it. It helps explain
which claims are contradicted, outside the permission scope, or not marked
as required. As discussed in Section~\ref{subsec:global}, judging the whole
response also requires checks of reasoning, consistency, and completeness.
The trace provides the individual claim decisions for that assessment.
For each recovered claim $i$, it contains eight elements:
\begin{itemize}
\item $s_i$, the \emph{response span}: the words in the response from which
the claim was recovered.
\item $q_i^*$, the \emph{recovered claim content}: what those words mean in
context, including the entities, dates, and qualifications needed to
preserve the claim's meaning.
\item $\widehat{m}_i$, the \emph{observed status marking}: how the response
presents the claim, using the labels \textsc{established},
\textsc{hypothetical}, or \textsc{fictional} introduced in
Section~\ref{subsec:contract-checks}.
\item $\mathrm{ES}_i$, the \emph{evidence state}: whether the task oracle
finds the claim \textsc{entailed}, \textsc{contradicted}, or \textsc{unknown}
relative to its reference evidence.
\item $a_i$, the \emph{permission check}: whether the claim is permitted
by the permission scope $\Gamma$.
\item $b_i$, the \emph{marking check}: whether the observed status marking
$\widehat{m}_i$ satisfies the required status marking $\mu$.
\item $\ell_i$, the \emph{claim label}: \textsc{grounded} (\Grd),
\textsc{licensed divergence} (\LD), or \textsc{hallucination} (\Hall),
as assigned by the decision rule.
\item $r_i$, the \emph{reason code}: the reason for a violation, if one is
identified, such as \textsc{out-of-scope} or \textsc{marking-failure}.
\end{itemize}
We write the record for claim $i$ as
\begin{equation}
\tau_i=(s_i,q_i^*,\widehat{m}_i,\mathrm{ES}_i,a_i,b_i,\ell_i,r_i).
\label{eq:claim-trace}
\end{equation}
\end{samepage}
If the decision rule does not require a check, its result is recorded as
\emph{not evaluated}, not as passed. The records for the individual claims
together form the trace for the response. Procedural failures are recorded
alongside these records; the affected claims remain unlabeled.

For the third claim in Figure~\ref{fig:claim-label-annotation}, $s_3$ is the
temple-entrance sentence, $q_3^*$ is the proposed placement,
$\widehat{m}_3$ is \textsc{hypothetical}, and $\mathrm{ES}_3$ is \textsc{unknown}.
The permission and marking checks both pass, giving $\ell_3=\LD$ without
a violation reason. The figure encloses the trace for all four claims.
The trace must also make omissions and failed processing visible.
Appendix~\ref{app:diagnostics} defines recovery coverage for that purpose;
answering the whole task remains a separate question.

An evaluation can summarize the response with counts of each label while
retaining the individual reasons. Appendix~\ref{app:diagnostics} gives an
optional rule that flags checked hallucinations and records incomplete
evaluation. The reporting policy is specified for the task and leaves claim
labels unchanged. Priority~4 in Section~\ref{sec:agenda} examines additional
checks of the whole response.

To summarize, the label of a claim depends on three results. The task
oracle gives the evidence state of the claim. The permission check asks
whether the task allows the claim. The marking check asks whether the
response presents the claim as required. An unknown or contradicted claim
therefore receives licensed divergence when both checks pass, and
hallucination otherwise.

\section{Resource Mapping}\label{sec:methodology}

This section analyzes how existing evaluations handle the three fields of
the truth contract: the reference evidence, the permission scope, and the
required status marking. The goal is to identify what current evaluations
can and cannot assess, and therefore which needs the framework of
Section~\ref{sec:framework} addresses.

We analyze 53 \emph{evaluation resources}. An evaluation resource is any
published work that specifies how model outputs are judged: a benchmark, a
dataset together with its evaluation protocol, a task suite, a metric, or
an evaluation study. A dataset alone is not enough, because it supplies
inputs and targets but does not decide how outputs are judged. For
CNN/DailyMail, for example, the corpus provides news articles, and the QAGS
metric defines the consistency check \citep{hermann_teaching_2015,
wang_asking_2020}. For each resource, we therefore analyze its
\emph{protocol}: the reference it uses, the content its task allows, the
presentation it requires, and how its scoring checks these points.

The analysis focuses on what happens when a task can permit unknown or
contradicted claims, because this is where the truth contract changes the
evaluation. If the permission scope is empty, every such claim is a
hallucination, whatever its marking. In the museum task, evaluating the
reconstructed placement of the stele requires three steps for the same
claim: recording that the placement is unknown in the reference, checking
that the task allows a plausible reconstruction, and checking that the
response presents the placement as a possibility.

We analyze 53 evaluation resources. Each field of the truth contract is
checked by some of them, and several resources check two fields together.
The fields, however, are checked in different kinds of tasks, and no
resource combines all three for the same claim. This gap is what the truth
contract addresses. Section~\ref{subsec:selection} explains how we selected
the resources, Section~\ref{subsec:criteria} how we read each protocol,
Section~\ref{subsec:families} how we group the resources into four
families, Section~\ref{sec:mapping} what each family checks, and
Section~\ref{subsec:gap} what is missing.

\subsection{Selection}\label{subsec:selection}

The analysis must cover the full range of permission scopes: tasks where
nothing beyond the reference is allowed, tasks that regulate how to answer,
and tasks that request new content. We started from the datasets and
benchmarks discussed in the surveys cited in this paper
\citep{ji_survey_2023,huang_survey_2025,jiang_survey_2024,
franceschelli_creativity_2024}. We then added resources for task
categories that these surveys cover less: attribution and citation,
abstention and uncertainty expression, false premises and counterfactual
reasoning, role-playing, and research proposals. Every retained resource
meets three conditions:
\begin{itemize}
\item it defines how an answer, a text, or a claim is judged: against
reference evidence, task instructions, or human ratings;
\item its task definition and scoring procedure are published, with
prompts, rubrics, or annotation guidelines when they exist;
\item it informs at least one field of the truth contract.
\end{itemize}
For each resource, we read the primary paper and its published prompts,
rubrics, or annotation guidelines. The aim is to cover the range of
permission scopes and the closest precedents for each field, not to list
every resource in the literature.

\subsection{Reading Each Protocol}\label{subsec:criteria}

For each resource, we record the evaluated unit and answer three questions,
one for each field of the truth contract:
\begin{itemize}
\item \textbf{Reference and check.} Which material or procedure establishes
support, contradiction, or task success?
\item \textbf{Permission scope.} Which additions, alternatives, or
exclusions does the task allow?
\item \textbf{Required status marking.} How must the response present its
content, and does the scoring check it?
\end{itemize}
The evaluated unit matters because a check covers only its own unit.
A correct final answer, a well-rated story, or a program that passes its
tests says nothing about the evidence state of each claim in an
accompanying explanation.

The table has no column for observed status marking. Observed marking
describes how one response presents a claim: as a fact, a possibility, or
fiction. It belongs to a response, not to a protocol. A protocol can only
state which marking it requires and whether its scoring checks it. The
table records these two points.

To keep the table readable, short symbols replace long descriptions:
\begin{itemize}
\item In the permission column, \Stated{} means that the task instructions
or rubric state the condition; \Weak{} means that we infer it from the task
type. PopQA, for example, never states that answers may not add unsupported
content, but a factual question with one target answer implies it
\citep{mallen_when_2023}.
\item In the marking column, \Stated{} means that the protocol requires a
presentation and its scoring checks it; \Weak{} means that the protocol
accepts a presentation, or requires one without checking it.
\item \Lacks{} means that we found no condition in the protocol; \Varies{}
means that the condition is set separately for each subtask or query.
\end{itemize}

Finally, we define what it means for a resource to apply the truth
contract. For the same claim, the resource must:
\begin{itemize}
\item record the evidence state of the claim, for example that the claim is
unknown in the reference;
\item state when the task permits an unknown or contradicted claim;
\item state which marking such a claim requires, and check it.
\end{itemize}
A resource that never accepts an unknown or contradicted claim does not
meet this criterion: its permission and marking checks cannot change the
label of a claim. Section~\ref{subsec:gap} uses this criterion to answer
our question.

\subsection{Four Families of Resources}\label{subsec:families}

The 53 resources cover ten task categories, from fact checking to
role-playing. These categories describe what each resource asks, but not
how it relates to the truth contract. We therefore group them by
permission scope. Permission is the field that varies most across tasks,
and it decides whether an unknown or contradicted claim can ever be
accepted.

We place each task category by asking three questions about its principal
task, in this order:
\begin{enumerate}
\item \emph{Are the evaluation rules set separately for each subtask?}
If so, the category is a mixed suite: its permission and marking can only
be read subtask by subtask.
\item \emph{Does the task request content that the reference does not
entail?} Stories, alternative uses, solutions, research proposals, and
in-character replies are such content. If so, the category requests new
content.
\item \emph{Does the task add a rule on whether, how, or under which
condition to answer?} Examples are abstaining, expressing uncertainty,
citing sources, correcting a premise, reasoning under a stated condition,
and satisfying explicit request constraints. If so, the category regulates
answers. Otherwise, it allows supported content only.
\end{enumerate}

These questions give four families:
\begin{itemize}
\item \textbf{Supported content only} (IDs 1--23): factuality evaluation,
including fact checking, factual question answering, summarization, and
answers based on retrieved context. The response must be supported by a
reference: the permission scope is empty, whether the protocol states it
or the task implies it.
\item \textbf{Regulated answers} (24--33): intent evaluation, attribution
and citation, abstention and uncertainty expression, and false premises and
counterfactual reasoning. The response must still be supported, but the
task adds a rule on how to answer. In counterfactual tasks, the stated
condition is part of the reference.
\item \textbf{Requested new content} (34--50): creative writing, divergent
thinking and linguistic creativity, problem solving and scientific
ideation, and role-playing and fictional-world consistency. The task asks
for content beyond the reference, within stated constraints.
\item \textbf{Mixed suites} (51--53): multi-task evaluation, with
BIG-Bench, BIG-Bench Hard, and CreativityPrism. Unlike the other three
families, a suite does not have one principal task. It gathers tasks that
could each belong to a different family: CreativityPrism, for example,
combines writing, divergent thinking, and reasoning tasks. Each task keeps
its own targets and scoring rules. BIG-Bench lets every task define its own
metric, and BIG-Bench Hard keeps a separate answer space for each selected
task. The shared protocol fixes how tasks are run and scored, not what
content they permit or how it must be presented.
\end{itemize}

The questions apply to the principal task of a category, not to every
rule of every resource. Several factuality protocols also accept or require
nonanswers, such as SimpleQA and HalluRAG
\citep{wei_measuring_2024,ridder_hallurag_2025}. They stay in the first
family because their main score measures support by the reference;
Section~\ref{sec:mapping} discusses their answer rules. Similarly,
WritingBench does not apply one fixed scoring grid. For each writing
request, it generates evaluation criteria adapted to that request and to
any material supplied with it \citep{wu_writingbench_2025}. Some requests
call for factual content and others for invented content, so the
permission scope changes from one request to the next. WritingBench
nevertheless stays in creative writing, because producing written
responses is its principal task.

\subsection{What Each Family Checks}\label{sec:mapping}

We now summarize, for each family, what its protocols check and what they
cannot evaluate. Table~\ref{tab:resource-mapping} gives the details for
each resource.

\paragraph{Supported content only}
These protocols check the reference evidence, but on units of different
sizes: a supplied claim (ID~1), a sentence (IDs~10, 15, 18), a span
(ID~23), or a final answer (e.g., IDs~3 and~5). When only
the final answer is scored, the other claims of the response receive no
evidence state. Some protocols also check how the answer is presented, for
example by accepting hedging (IDs~2 and~4) or by requiring the model to
admit that it cannot answer (IDs~15, 18, and~21). These rules can lead to a nonanswer, but never to accepting
an unknown claim. In this family, every unknown or contradicted claim is an
error.

\paragraph{Regulated answers}
These protocols add a rule to the answer. Intent evaluation (ID~24) restricts
content through explicit request constraints. The other categories
regulate how the answer is presented:
\begin{itemize}
\item \emph{whether to answer}, for example by abstaining (ID~27);
\item \emph{how confident the wording is}, for example by expressing
uncertainty (IDs~28--30);
\item \emph{where the content comes from}, for example by citing sources
(IDs~25 and~26);
\item \emph{which premise holds}, for example by correcting a false
assumption or reasoning under a stated condition (IDs~31--33).
\end{itemize}
None of these rules is a required status marking in our sense, which
concerns whether a claim is presented as a fact, a possibility, or fiction.
A citation names a source; it does not present a claim as a hypothesis.
Expressed uncertainty (IDs~28--30) follows what the model is estimated to know,
not the evidence state relative to a designated reference. In
counterfactual tasks (IDs~31 and~33), the stated condition is part of the reference, so a
supported answer is grounded, not a licensed divergence. Like the first
family, this family therefore requires supported content: its rules
regulate how supported content, or its absence, is presented. The one
exception is LoGU (ID~29), which no longer counts a refuted claim as an
error once it is hedged; Section~\ref{subsec:gap} explains why this is not
a permission in our sense.

\paragraph{Requested new content}
These protocols state permission explicitly, and the permission changes
from task to task: alternative concepts (ID~41), new uses of the available
objects (ID~44), programs that avoid named techniques (ID~47), fiction
within cue words or a plot (IDs~35, 37, and~38), or new research methods
(ID~49). Their checks, however, judge the output as a whole: the
creativity of a story (IDs~34--38), the feasibility of a solution
(ID~44), the tests of a program (IDs~46 and~47), or the novelty of a
proposal (IDs~42 and~49). Reference texts often serve to
compare quality rather than to provide evidence (IDs~38 and~48). Status marking is rarely
required, and when it is, as with proposal headings (ID~49) or a character's
unawareness of later events (ID~50), it is not scored for each claim. Nothing therefore
requires an invention stated as a fact and the same invention presented as
a hypothesis to receive different scores.

\paragraph{Mixed suites}
The shared protocols of these suites (IDs~51--53) set no general permission or marking
rule. These fields are set by each task, so they can only be assessed task
by task.

\subsection{What Is Missing}\label{subsec:gap}

We can now answer the question of this section. No resource in the mapping
can accept an unknown or contradicted claim under stated permission and
marking conditions while recording that claim's evidence state. The closest
resources fully cover at most two of the three fields
(Table~\ref{tab:precedents}):
\begin{itemize}
\item HalluRAG and ALCE record evidence for sentences or statements and
accept no unsupported claim. HalluRAG checks a required admission that the
question cannot be answered; ALCE requires citations, which identify
sources rather than the status of a claim.
\item LoGU records evidence for each claim and does not count a refuted
claim as an error when the claim is expressed with uncertainty. This
acceptance is not tied to a permission stated by the task: any claim can be
hedged, and the hedge is judged against what the model is estimated to
know, not against the reference.
\item HIC-Bench, NeoCoder, and \citet{si_ideas_2025} permit new content
under explicit constraints, but judge the output as a whole. NeoCoder
computes novelty over the techniques a program uses, not over claims.
\item TimeChara restricts what a character may know at a given time and
checks that a response reveals nothing beyond it. It evaluates whole
responses and does not score expressed unawareness separately.
\end{itemize}

The state of the art therefore checks each field, but does not connect
them. The first two families record claim-level evidence and check
marking, but either reject every unknown or contradicted claim or, as in
LoGU, accept any such claim once it is hedged, without a permission stated
by the task. The third family
permits such claims, but does not evaluate them one by one. For the
temple-entrance placement, a protocol from the first two families rejects
the claim whether or not it is presented as a possibility; a protocol from
the third family does not check how it is presented. The truth contract is designed
to connect these checks. It records the evidence state of each claim,
checks whether the task permits the claim and how the response presents
it, and assigns one claim label. Whether evaluators can apply it reliably
remains to be tested (Section~\ref{sec:agenda}).

For mixed suites and for protocols that write a rubric for each query, such
as FaithQA and WritingBench, this conclusion concerns the shared protocol;
a particular subtask or rubric could add further conditions.

The mapping thus finds the three checks in separate places. The next
section shows why they must be combined. Four examples keep a response
fixed and change one field at a time; each change alters the label of the
same claim.

\section{Examples}\label{sec:cases}\label{sec:examples}

The four constructed examples illustrate how evaluation depends on the
truth contract while keeping the response text, recovered claim content,
and observed status marking fixed within each comparison.
Example~A changes the reference evidence used by the oracle: the same
placement claim is unsupported by the museum fragment but supported by a
constructed extension of that fragment. Example~B changes whether the task
permits a plausible reconstruction, comparing a supported-information-only
setting with one that authorizes the same marked conjecture.
Example~C changes the required status marking: the same conjecture fails a
requirement for an explicit ``Hypothesis'' heading but satisfies a requirement
for a conjecture cue within the sentence. Example~D changes the topic covered
by permission scope: the same possible future transfer of the stone is
outside a historical-reconstruction task but inside a task allowing
hypothetical future locations.
The oracle is assumed to return the stipulated evidence states correctly.
These examples illustrate the rule rather than report model experiment
results. Figure~\ref{fig:example-settings} presents the two settings and
predicted labels for each comparison.

\paragraph{Example A: changing the task oracle}
The response is ``The complete stele stood near a temple entrance.''
This example shows why the reference evidence must be fixed for each
evaluation: the same claim can have different evidence states under
different references.
\par\textbf{Fixed.} Response, claim, observed factual assertion,
$\Gamma=\varnothing$, and no additional marking requirement for supported facts.
\par\textbf{Changed.} $O_1$ uses the museum fragment, which leaves the
placement unknown. $O_2$ uses the same fragment plus the stipulated sentence
``The complete stele stood near a temple entrance.'' Each oracle is fixed
within its evaluation design.
\par\textbf{Predicted result.} The unknown claim receives \Hall{} with
\textsc{out-of-scope} under $O_1$; the entailed claim receives \Grd{} under
$O_2$. The additional reference sentence supplies test evidence; it does
not establish a historical fact about the original placement.

\paragraph{Example B: allowing a reconstruction}
The response is ``One possible reconstruction places the complete stele
near a temple entrance.''
\par\textbf{Fixed.} The reference oracle, proposed placement, its unknown
evidence state, and the sentence's observed marking as a possibility.
Both settings require any permitted reconstruction to be marked as such.
\par\textbf{Changed.} The first setting allows supported information only
($\Gamma_1=\varnothing$). The second allows plausible reconstructions of the
original placement ($\Gamma_2$ includes this proposal).
\par\textbf{Predicted result.} The same response receives \Hall{} with
\textsc{out-of-scope} in the first setting and \LD{} in the second.
Its hedging satisfies the marking requirement but cannot itself authorize
content that the first task excludes.

\paragraph{Example C: changing required status marking}
The response is again ``One possible reconstruction places the complete
stele near a temple entrance.''
\par\textbf{Fixed.} The reference oracle, permission for that reconstruction,
claim content, unknown evidence state, and observed sentence-level marking.
\par\textbf{Changed.} $\mu_1$ explicitly requires the heading ``Hypothesis''
for a reconstruction. $\mu_2$ accepts an explicit sentence-level conjecture
cue, such as ``One possible reconstruction.'' This is a constructed contrast
between two presentation requirements, not a claim that a heading is
universally necessary for marking a conjecture.
\par\textbf{Predicted result.} The unchanged response lacks the required
heading under $\mu_1$ and receives \Hall{} with \textsc{marking-failure}.
It satisfies $\mu_2$ and receives \LD{}. Here the requirement changes, not
what the response actually says or how it presents the placement.

\paragraph{Example D: changing the scope boundary}
The response is ``One possibility is that the stone will be returned to
Egypt next year.'' The statement is a constructed future scenario.
\par\textbf{Fixed.} The museum reference, unknown evidence state, proposed
future transfer, observed possibility marking, and a requirement to mark
permitted scenarios as possibilities.
\par\textbf{Changed.} $\Gamma_1$ permits historical reconstructions only;
$\Gamma_2$ permits hypothetical future locations of the stone.
\par\textbf{Predicted result.} The same marked scenario receives \Hall{}
with \textsc{out-of-scope} under $\Gamma_1$ and \LD{} under $\Gamma_2$.
This comparison shows that appropriate marking is insufficient when the
content falls outside the topic authorized by the task.

These examples isolate changes to the truth contract while keeping the
response fixed. The research agenda develops datasets and methods for
these evaluations.

\section{Research Agenda}\label{sec:agenda}

This section outlines the research needed to test the framework and assess its usefulness in real tasks.
The examples show the evaluations that a truth contract makes explicit.
The next step is to build datasets with annotated contracts, develop methods
that apply them to responses, and study their use in real tasks. The seven
priorities below organize this work around evidence, permission, and marking,
while keeping creative quality and overall task success visible.

\paragraph{1. Datasets with annotated truth contracts}
A dataset should provide the task context, designated evidence, permission
scope, required status marking, and generated responses. Its claim annotations
should record content, observed marking, evidence state, label, and reason
for any violation. Include factual tasks, permitted reconstructions, fiction,
and tasks that explicitly require invention, so that the different scope
conditions can be evaluated.

An annotation guide should explain how to identify the three contract fields
and apply them to claims. Independent annotators can then record agreement,
resolve differences, and retain ambiguous interpretations as evaluation
failures. The dataset should include responses with correct marking, missing
marking, and additions outside the permitted scope, rather than only changes
to one constructed response.

\paragraph{2. Methods for contract-aware evaluation}
An evaluation method should recover claims and observed marking, verify
evidence, and apply permission and marking requirements. It should return
the claim trace so that a label can be connected to the checks that produced
it. Compare human, automated, and combined implementations using the same
task conditions, and report claim recovery, label accuracy, error types,
and evaluation cost separately.

Controlled comparisons can isolate the role of each contract field, as in
Examples~A--D. A comparison with an instruction-following rubric should give
both methods access to the same evidence and task requirements. Independent
judgments of task acceptability provide a further comparison alongside
agreement with the proposed rule. This distinguishes applying the rule
correctly from the practical value of its decisions.

\paragraph{3. A potential robustness test across styles}\label{par:style-scale}
Work on style transfer examines changes in wording while preserving content
\citep{rao_dear_2018,briakou_evaluating_2021}. Work on model-based evaluation
also motivates studying sensitivity to style and differences between human
and automated judgments \citep{feuer_style_2025,lyu_converge_2026}.
These studies suggest a potential test of evaluator robustness: compare
responses written in different styles under the same truth contract.

A change in wording can also change what a claim means or how it is
presented. Independent checks must therefore confirm that the recovered
claim content $q^*$ and observed status marking $\widehat{m}$ remain the
same before comparing labels. Match the claims across responses using
these two records and keep $O$, $\Gamma$, and $\mu$ fixed. The decision rule
predicts the same label for each matched claim; the study would test
whether evaluators reproduce this result.

Report missed or added claims, incorrect splits or merges, changes in
recovered meaning or status, and different labels for matched claims.
Also report recovery coverage, since omissions can change a response
summary even when matched claims retain their labels. If the wording
changes a claim's content or status, that pair cannot isolate the effect
of style on evaluation.

\paragraph{4. Response-level evaluation}
A response-level evaluation should report claim labels and recovery coverage,
then check reasoning, consistency, completeness, relevance, and task success.
For coverage, compare the recovered claims with an independently annotated
list of the claims expressed in the response. This measures what was recovered;
completeness separately checks whether the response supplied what the task
requested.

Compare summaries based on label counts, any hallucination, or the severity
of errors, using the same claim decisions. Appendix~\ref{app:diagnostics}
gives one optional reporting rule. Studies should examine how these summaries
affect model comparisons and how to check response-level constraints, such
as a request for exactly one reconstruction. Creative quality should
remain an explicit outcome.

\paragraph{5. Applications and hallucination reduction}
The museum task provides one application: a factual explanation may include
a useful reconstruction, but should preserve the historical reference and
make that reconstruction clear. A study can compare factual-only responses
with responses that include permitted additions, using judgments of clarity,
usefulness, and compliance with the contract. Other creative writing and
problem-solving tasks can examine the same relationship between allowed
content and task success.

Mitigation studies should compare retrieval, verification, abstention, and
generation constrained by task rules. Report reductions in hallucination
together with the amount and usefulness of grounded and licensed content.
This makes visible whether a method improves the response or merely removes
content that the task requested or allowed.

\paragraph{6. Generalization}
Extend the datasets and evaluation methods to other domains, genres, and
languages. Compare agreement, errors, and cost for each contract field.
Identifying permitted content and interpreting its status may require
different checks across tasks. These comparisons should establish where
the definitions can be applied directly and where task-specific guidance
is needed.

\paragraph{7. Updating contracts during tasks and actions}
In a task with several steps, new evidence may become available and later
actions may rely on earlier claims. Record the contract used at each step,
the task instruction that permits an update, and how an incorrect claim
affects later actions. Updates must follow the task protocol and remain
independent of an attempt to excuse a generated response. Compare this
record with an evaluation using a fixed contract on the same action outcomes.

\section{Discussion}\label{sec:discussion}

\subsection{What Is Relative and What Is Not}\label{subsec:relative}

Our position concerns the conditions for assigning an evaluation label.
A task can authorize a possibility without making it true. Likewise,
changing the designated oracle changes the evidence relation used for
evaluation, not the underlying world's facts. Under the proposed convention,
H covers unknown or contradicted content that is not permitted or not presented
as required. It also covers supported facts explicitly excluded by a requirement
for invented content. A permitted contradiction remains contradicted even when
it receives LD, just as an excluded supported fact remains entailed when it
receives H. The evidence state records what the reference establishes; the label
records whether the claim satisfies the task contract. Keeping both makes
these different judgments explicit.

Theoretical work provides context for reliability concerns. Some results
describe minimum error rates under assumptions about how a model expresses
confidence; others examine what a computational system can guarantee
\citep{kalai_calibrated_2024,xu_hallucination_2024,banerjee_llms_2024}.
Their assumptions differ, and they do not fix the error rate of every
deployed model or rule out negligible rates in a specific setting
\citep{suzuki_negligible_2025}. Our argument does not require proving that
hallucination is unavoidable: it concerns how to evaluate content against
specified evidence and task conditions.

The AA-Omniscience snapshot provides a descriptive
illustration \citep{jackson_aaomniscience_2025,artificialanalysis_omniscience_leaderboard_2026}.
Appendix~\ref{app:omniscience} gives its date, metrics, and limitations.
Comparing different models at one time does not isolate the effect of model
size or show that truth-contract annotation improves evaluation.

\subsection{Interpreting the Response-Level Record}

Section~\ref{subsec:response} leaves open how claim labels should be combined.
An overall judgment summarizes the claims checked under the contract and
the declared recovery coverage. Reasoning, completeness, and creative
quality are assessed through their own task criteria. The optional rule in
Appendix~\ref{app:diagnostics} uses \textsc{indeterminate} when the evaluation
cannot be completed. This records a limit of the evaluation, not necessarily
an error by the model, and should be reported.

These distinctions matter for mitigation. A claim trace can reveal whether a
method reduced contradictions, removed unauthorized additions, or improved
marking. Creative-task assessment then asks whether useful permitted content
was preserved. Giving more weight to serious errors may help decide which
responses to review first. That score cannot change the labels of their
individual claims.

\subsection{Limitations}

The truth contract is a proposal for claim-level evaluation, and its
reliability in practice remains to be measured. Applying it requires a
contract stated for the task, claims recovered with their context, and
completed evidence checks. When a word such as ``may'' or a fictional
context leaves the observed marking unclear, the claim is recorded as an
evaluation failure rather than given a label.

Claim labels evaluate each claim against the contract. Reasoning,
consistency, completeness, and constraints on the whole response require
additional checks, which Section~\ref{sec:agenda} discusses.

Finally, many protocols in the mapping use a language model as the judge
(e.g., IDs~4, 8, 18, 27, 42, and~50). LLM judges are sensitive to the order
and length of responses, favor their own generations, and can fail to
recognize hallucinated content
\citep{wang_fair_2024,zheng_judging_2023,panickssery_llm_2024,li_halueval_2023,gu_survey_2024}.
The truth contract does not remove this limitation, but the claim trace
shows which check a judge got wrong.

\section{Conclusion}\label{sec:conclusion}

Hallucination evaluation should consider what the reference evidence
establishes and what the task permits. We propose a truth contract with
three components: the task oracle, which specifies the reference and checking
procedure; permission scope, which states what content may be added, changed,
or excluded; and required status marking, which states how that content must
be presented.

This contract distinguishes grounded claims, hallucinations, and licensed
divergence without treating permission as evidence of truth. An unknown or
contradicted claim can be licensed when the task permits it and its status
is presented as required. A supported fact can still violate an explicit
instruction requiring invention. The evidence state remains visible
alongside the label, so the reason for either judgment can be inspected.

The resource mapping compares how 53 selected evaluations represent evidence
and task conditions. The four constructed examples show how changing the
reference, permission, or required marking changes a label for the same
response. These distinctions provide a basis for datasets, evaluation
methods, and applications that check factual reliability while preserving
content the task permits. Creative quality and success on the whole task
remain part of the evaluation, alongside the individual claim decisions.

\phantomsection
\makeatletter\def\@currentlabel{A}\makeatother\label{app:diagnostics}

Section~\ref{sec:framework} defines how to recover, verify, and label claims.
This appendix explains what to report: the individual decisions, any
evaluation failures, and separate assessments of creative-task success.
It also describes an optional way to combine labels.


\paragraph{Reporting and aggregation details}
Section~\ref{subsec:response} defines the claim trace and leaves the global
verdict as a research question. One possible rule requires a minimum level
of recovery coverage, declared before evaluation, and follows this order:
\begin{enumerate}
\item Report \textsc{contract-violating} if any reliably checked claim receives H.
\item Otherwise, report \textsc{indeterminate} if too few claims were recovered
or a failure prevents the required checks.
\item Otherwise, report \textsc{contract-compliant} for the completed checks.
\end{enumerate}
This is an option to test, not the framework's default. A study using it must
publish its coverage threshold, claim trace, and evaluation failures. A
favorable result cannot certify claims that were not recovered.

Creative-task success is \textsc{pass}, \textsc{fail}, \textsc{not assessed},
or a task-specific score under stated criteria. Report those criteria and
unit of analysis. Novelty, usefulness, quality, and diversity should not be
silently substituted for one another.

An overall score may use label proportions, give more weight to serious
errors, or follow task-specific rules. State the rule before evaluation,
retain every claim label, and report whether other reasonable rules change
the conclusions. Checks of reasoning, consistency, completeness, relevance,
and the number of requested additions remain separate.

Claims that are individually permitted may contradict one another. If the
oracle is consistent and claims are correctly interpreted in the same context,
however, two contradictory claims cannot both be entailed. An apparent instance
requires checking the oracle and recovered claims before interpreting the labels.

\paragraph{Procedural failures}

A \emph{procedural failure} occurs when the evaluator cannot complete a
required step. It is recorded instead of assigning \Grd, \Hall, or \LD{} to
the affected content. Labeling requires a claim with a clear meaning, a
specified contract, and a completed evidence check. The protocol specifies
the oracle; the task conditions specify permission and required marking.
The following failures prevent one or more of these requirements from being met.

\paragraph{Failures of claim recovery}
The evaluator may miss a claim, add one absent from the response, merge claims
that need separate checks, or split one claim into redundant parts. It may
also change the meaning or observed status while recovering a claim.
Here, \emph{canonicalization} means expressing the recovered content as
$q^*$ while preserving its meaning and context. It is part of claim recovery,
not an additional stage of the oracle. If the meaning of the affected text
cannot be resolved, no label is assigned to it.

\paragraph{Failures of the truth contract or task oracle}
The evaluator may instead be unable to apply the contract to a claim it has
recovered. Four failures have this effect.
\begin{description}
  \item[Truth-contract specification failure.] The protocol and task conditions
        do not specify which oracle to use, what content is permitted or
        excluded, or how it must be presented.
  \item[Task-oracle specification failure.] The oracle's sources or checks are
        not defined precisely enough. For text, this can include unclear source
        authority, dates of validity, or rules for resolving conflicting evidence.
  \item[Task-oracle adequacy failure.] Required sources or checks are unavailable,
        a source version does not meet the protocol, or an unresolved conflict
        prevents the specified procedure from being applied.
  \item[Adjudication failure.] The evaluator cannot reach one evidence state
        using the specified procedure.
\end{description}
For each failure the evaluator records the failure and leaves the affected span
unlabeled.
An available source that neither supports nor contradicts a claim can yield
\textsc{unknown} after a completed check. A source that cannot be accessed
instead prevents that check. The failure must not be automatically converted
to \textsc{unknown}. Under the optional overall reporting rule above, a
reliably checked H takes priority; otherwise a blocking failure produces
\textsc{indeterminate}.

Recent fact-verification work examines difficulties in separating such
outcomes. The way unknown examples are built affects what a verifier learns
and may hide difficulty in deciding the evidence state
\citep{qiu_evidence_2026}. Separately, a single global faithfulness label can
hide disagreement about individual sentences through an averaging bias
\citep{zhang_averaging_2026}.

\paragraph{An example}
Suppose two annotators read the closing span of a museum panel, ``the winter
that would not lift''.
One recovers a claim about the severity of that winter; the other recovers no
truth-conditional claim at all.
The two annotators disagree about which claim the span commits to, not about
which label a shared claim deserves.
The evaluators must first try to resolve the difference in interpretation.
If it remains unresolved, they record a claim-recovery failure for that text,
rather than compare labels assigned to different interpretations.

\appendixsection{AA-Omniscience Leaderboard Snapshot}%
\phantomsection
\makeatletter\def\@currentlabel{B}\makeatother\label{app:omniscience}

Section~\ref{subsec:relative} cites AA-Omniscience as evidence that scale and
recency are not sufficient proxies for factual reliability.
This appendix records the snapshot's metrics, date, and limits. The graphics
are reproduced from the source named in the caption.

AA-Omniscience's full leaderboard set contains 6,000 short-answer questions
across 42 topics and six domains.
Models are instructed to answer when confident and otherwise abstain. An
automated grader assigns \textsc{correct}, \textsc{incorrect},
\textsc{partial answer}, or \textsc{not attempted}. The Omniscience Index
rewards correct answers and penalizes incorrect ones across the full set. The
benchmark-specific hallucination rate measures confidently wrong answers among
all non-correct answers. This metric is distinct from the claim labels in
our framework. Let $n_c$ count correct answers, $n_w$ incorrect answers,
$n_u$ partial answers, and $n_a$ questions not attempted, with
$N=n_{c}+n_{w}+n_{u}+n_{a}$. The Omniscience Index is
$100(n_{c}-n_{w})/N$, and the AA-Omniscience hallucination rate is
$n_{w}/(n_{w}+n_{u}+n_{a})$ \citep{jackson_aaomniscience_2025}.
The complete 6,000-question leaderboard set is private; the released dataset
contains 600 questions and is intended for aggregate inspection rather than
fine-grained topic estimates
\citep{artificialanalysis_aaomniscience_public_2025}.

Figure~\ref{fig:aa-omniscience-snapshot} reports the August 26, 2026 snapshot.
The release-date panel plots the Omniscience Index rather than the
hallucination rate.
